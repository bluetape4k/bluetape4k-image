# #646 JNI WebP 무손실 계약 검토

## 범위와 결론

`JVipsWebpWriter`의 일반 인코딩 호출을 기존 바인딩의 WebP 전용 호출로 교체했다.
공개 API와 예외 변환, 네이티브 이미지 소유권은 바꾸지 않았다. 새 의존성은 없다.
두 구현의 회귀 테스트는 `images-vips-api`의 기존 시험용 공통 모듈을 재사용한다.

| 독립 검토 | 실행 모델과 추론 수준 | 판정 | P0/P1 |
|---|---|---|---|
| code-reviewer | gpt-5.6-luna / max | APPROVE | 0 |
| architect | gpt-5.6-sol / high | CLEAR | 0 |

모델 변경 없이 설치된 역할 계약으로 실행했다. 검토자는 소스와 고정 바인딩,
리더의 실제 실행 로그를 읽었으며 테스트를 중복 실행하지 않았다.
이 표는 두 독립 검토의 근거이며 일곱 개 모델이 검토했다는 뜻은 아니다.

## 검증 근거

- Linux amd64 JNI 수정 전: 공개 `lossless=true` 경로가 `VP8 `을 반환하여 `VP8L` 검사 실패.
- 수정 후 같은 계약: 1개 통과, 실패·건너뜀 0.
- 최종 JNI `JVipsImageTest`: 21개 통과, 실패·건너뜀 0.
- macOS FFM 모듈: 81개 통과, 실패·건너뜀 0.
- `checkProductionAbi`: 공개 JVM 모듈 10개 통과.
- 변경 writer와 새 공통 fixture를 지정한 `detekt`: 통과.
  최초 숫자 상수 경고는 의미 있는 명명 상수로 수정한 뒤 전체 FFM과 JNI 계약을 다시 실행했다.

## 반론과 남은 범위

픽셀 비교만으로는 작은 이미지의 우연한 동일성을 배제하기 어려우므로 실제 WebP 청크와
픽셀 결과를 함께 검사한다. 완전히 투명한 픽셀의 숨겨진 RGB 보존은 요구하지 않는다.
JNI 검증은 Linux amd64에서 수행했다. macOS ARM64에서 포함된 JNI 바이너리가
로드되지 않아 건너뛴 결과는 통과 근거에서 제외했다. 다른 플랫폼 지원 전체를 보증하지 않는다.
기존 WebP `effort` 처리 방식은 이번 옵션 누락 수정에 포함하지 않는다.
