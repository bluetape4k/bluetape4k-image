# Issue #1 OCR Module

## Context

Issue #1 added `bluetape4k-images-ocr`, a Tess4J/Tesseract OCR module for `ImmutableImage`.

## Decision

Keep OCR out of the core `images` module. Expose `OcrOptions`, `OcrEngine`, blocking `extractText`, and coroutine `suspendExtractText`, while keeping Tess4J mutable runtime state behind a per-call internal adapter.

## Outcome

- Registered `:bluetape4k-images-ocr`.
- Added always-on unit tests plus native/container gated tests.
- Updated README/README.ko, module READMEs, root diagrams/charts, AGENTS, CI, and Nightly.
- Created follow-up issue #169 for PaddleOCR evaluation because research showed the advanced document OCR scope is larger than issue #1.

## Future Agent Notes

- Do not expose Tess4J types in public constructors while Tess4J remains an `implementation` dependency.
- Keep host-native OCR tests behind `-Docr.enabled=true` and Docker smoke tests behind `-Docr.container.enabled=true`.
- When OCR research expands beyond Tess4J/Tesseract, create follow-up issues instead of broadening the active implementation.
