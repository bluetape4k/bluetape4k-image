# Issue #1 OCR 모듈

## 배경

Issue #1에서 `ImmutableImage`용 Tess4J/Tesseract OCR 모듈
`bluetape4k-images-ocr`을 추가했다.

## 결정

OCR은 core `images` 모듈에서 분리한다. `OcrOptions`, `OcrEngine`, blocking
`extractText`, coroutine `suspendExtractText`를 공개하되 Tess4J의 변경 가능한 runtime
상태는 호출마다 생성하는 내부 adapter 뒤에 둔다.

## 결과

- `:bluetape4k-images-ocr`을 등록했다.
- 항상 실행하는 단위 테스트와 native/container gate 테스트를 추가했다.
- README/README.ko, 모듈 README, 루트 다이어그램·차트, AGENTS, CI, Nightly를
  갱신했다.
- 조사 결과 고급 문서 OCR 범위가 Issue #1보다 크다고 판단해 PaddleOCR 평가를
  후속 Issue #169로 만들었다.

## 검증

- `./gradlew :bluetape4k-images-ocr:test --rerun-tasks --console=plain`: 테스트
  13개 중 10개 실행, 3개 건너뜀.
- `./gradlew :bluetape4k-images-ocr:build --console=plain`: 통과.
- `./gradlew :bluetape4k-images-ocr:koverXmlReport --console=plain`: 통과.
- `actionlint`: 통과.
- `git diff --check`: 통과.
- 다이어그램 gate:
  `nodes=12 routes=15 segments=36 badEndpointAngle=0 badBends=0 interiorCrossings=0`.

## 이후 작업자 참고 사항

- Tess4J가 `implementation` 의존성인 동안 공개 constructor에 Tess4J 타입을 노출하지
  않는다.
- host-native OCR 테스트는 `-Docr.enabled=true`, Docker smoke 테스트는
  `-Docr.container.enabled=true` gate 뒤에 둔다.
- OCR 조사가 Tess4J/Tesseract 범위를 넘어가면 진행 중인 구현 범위를 넓히지 말고
  후속 이슈를 만든다.
