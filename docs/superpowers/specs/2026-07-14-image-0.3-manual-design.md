# Image 0.3 Manual 설계

## 목표

`bluetape4k-image` 0.3.x에 충실한 bilingual manual을 publish한다. manual은 reader가 README archaeology에
의존하지 않고 pure-JVM Scrimage/Java2D path와 native libvips backend를 선택하고, OCR과 web framework를
통합하며, native resource를 안전하게 운용하고, runnable example로 학습할 수 있게 해야 한다.

## Release 경계

- release ref: `0.3.0`
- release commit: `a571c30004f571fe8cfcddc29670c1404d212ec6`
- release inventory: 15 Gradle project. 9 published library/BOM artifact, 5 runnable example, 1 benchmark project로 구성된다.
- authoring source: `develop` 위의 이 branch. API claim과 source link는 release ref 기준으로 resolve한다.
- 0.4-only barcode API, ZXing provider, Spring barcode example은 제외한다.

## Reader 계약

reader는 `io.github.bluetape4k:bluetape4k-dependencies`를 통해 하나의 ecosystem version을 선택한다.
manual은 reader에게 Image BOM 또는 개별 module version을 조율하라고 요구하지 않는다.

모든 release library, example, benchmark project는 English/Korean landing page를 가진다. library page는 selection,
lifecycle, configuration, failure, operation, testing, source evidence를 설명한다. example page는 workshop-grade로
작성하며 prerequisite, run command, observable result, diagnosis, next learning step을 포함한다.

## 정보 구조

1. Overview: product fit, installation, repository map, runtime boundary, version policy.
2. Guides: backend selection, format/codec decision, native memory, OCR setup, framework selection, testing,
   failure diagnosis, performance, learning path.
3. Core: immutable image model, loading/writing, transformation, filter, analysis, coroutine writer.
4. Native: Vips API, Java 21 JNI, Java 25 FFM, lifecycle, deployment requirement.
5. Integrations: CAPTCHA, OCR, Ktor, Spring Boot, storage, CDN, health, metrics.
6. Projects: 15개 release project 전체의 complete landing page.

## Diagram 체계

manual diagram은 established dark bluetape style을 사용한다. 각 diagram은 editable SVG와 2x PNG form,
visible 14x14 arrowhead, card 안에 포함되는 label, route가 겹치는 곳의 contrasting connector color를 가진다.
필수 diagram은 다음과 같다.

- repository와 learning map
- processing pipeline과 resource ownership
- backend/JDK decision map
- OCR과 web integration flow
- benchmark interpretation map

모든 diagram은 `bluetape-diagram` checklist와 full-size visual review를 통과한다.

## 검증

- documentation-only work를 위한 build task를 추가하지 않고도 Gradle settings inventory export가 immutable release
  inventory와 일치한다.
- manifest가 15개 release project를 모두 포함한다.
- English/Korean path와 section contract가 aligned 상태를 유지한다.
- 모든 source link가 `0.3.0`에서 resolve된다.
- Markdown, frontmatter, manifest, diagram contract가 통과한다.
- documentation-only CI를 사용한다. native, OCR, Testcontainers, security workflow는 해당 code가 영향을 받을 때만 실행한다.
