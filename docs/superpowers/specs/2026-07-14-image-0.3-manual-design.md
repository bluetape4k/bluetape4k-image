# Image 0.3 Manual Design

## Goal

Publish a release-faithful bilingual manual for `bluetape4k-image` 0.3.x. The manual must help readers choose between the pure-JVM Scrimage/Java2D path and the native libvips backends, integrate OCR and web frameworks, operate native resources safely, and learn through runnable examples without depending on README archaeology.

## Release boundary

- Release ref: `0.3.0`
- Release commit: `a571c30004f571fe8cfcddc29670c1404d212ec6`
- Release inventory: 15 Gradle projects — 9 published library/BOM artifacts, 5 runnable examples, and 1 benchmark project.
- Authoring source: this branch on `develop`; API claims and source links resolve against the release ref.
- Exclude the 0.4-only barcode API, ZXing provider, and Spring barcode example.

## Reader contract

Readers choose one ecosystem version through `io.github.bluetape4k:bluetape4k-dependencies`. The manual does not ask them to coordinate an Image BOM or individual module versions.

Every release library, example, and benchmark project receives an English and Korean landing page. Library pages explain selection, lifecycle, configuration, failures, operations, testing, and source evidence. Example pages are workshop-grade: prerequisites, run command, observable result, diagnosis, and a next learning step.

## Information architecture

1. Overview: product fit, installation, repository map, runtime boundaries, and version policy.
2. Guides: backend selection, format/codec decisions, native memory, OCR setup, framework selection, testing, failure diagnosis, performance, and learning paths.
3. Core: immutable image model, loading/writing, transformations, filters, analysis, and coroutine writers.
4. Native: Vips API, Java 21 JNI, Java 25 FFM, lifecycle, and deployment requirements.
5. Integrations: CAPTCHA, OCR, Ktor, Spring Boot, storage, CDN, health, and metrics.
6. Projects: complete landing pages for all 15 release projects.

## Diagram system

Manual diagrams use the established dark bluetape style. Each diagram has editable SVG and 2x PNG forms, visible 14x14 arrowheads, labels contained by cards, and contrasting connector colors where routes overlap. Required diagrams:

- repository and learning map
- processing pipeline and resource ownership
- backend/JDK decision map
- OCR and web integration flow
- benchmark interpretation map

Every diagram passes the `bluetape-diagram` checklist and full-size visual review.

## Validation

- Gradle settings inventory export agrees with the immutable release inventory without adding a build task for documentation-only work.
- The manifest covers all 15 release projects.
- English/Korean paths and section contracts remain aligned.
- Every source link resolves at `0.3.0`.
- Markdown, frontmatter, manifest, and diagram contracts pass.
- Documentation-only CI is used; native, OCR, Testcontainers, and security workflows run only when their code is affected.
