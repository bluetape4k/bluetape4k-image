# Issue 172 Design — Spring Boot OCR Example

## Context

Issue #172 asks for a Spring Boot example that exposes the existing
`images-ocr` OCR API through an application endpoint. It is a follow-up to the
core OCR work and must stay focused on application wiring rather than adding a
new OCR backend.

Current repository evidence:

- `examples/spring-boot-image-api` already defines the expected example shape:
  a non-published Gradle module, a compact Spring Boot 4 application, MockMvc
  integration tests, bilingual README files, README diagrams, and coverage in
  `.github/workflows/Examples.yml`.
- `images-ocr` exposes `OcrEngine`, `OcrOptions`, `OcrResult`, `OcrException`,
  `ImmutableImage.extractText`, and `ImmutableImage.suspendExtractText`.
- `images-ocr` native tests are gated by `-Docr.enabled=true` or
  `-Docr.container.enabled=true`, so an always-on example test must not require
  host Tesseract.
- Existing example diagrams are generated by
  `docs/scripts/generate-example-readme-diagrams.py` into
  `docs/images/readme-diagrams`.

## Goals

1. Add a runnable Spring Boot 4 OCR quickstart under
   `examples/spring-boot-ocr-api`.
2. Provide a multipart image endpoint that extracts text through
   `images-ocr`.
3. Keep local tests deterministic without requiring native Tesseract by
   injecting a fake `OcrEngine` in tests.
4. Document native Tesseract and traineddata requirements for real local runs.
5. Register the example in Gradle, root docs, repo guidance, and the Examples
   workflow.
6. Add README diagram assets that explain scenario, top-down layered
   architecture, and request sequence.

## Non-Goals

- No new OCR backend.
- No PaddleOCR or external service evaluation.
- No Ktor example; issue #173 owns that follow-up.
- No production authentication, rate limiting, file persistence, or queueing.
- No real host-native OCR requirement in normal CI.

## Design Options

### Option A — New Spring Boot OCR API Example Module

Create `examples/spring-boot-ocr-api` with:

- `POST /api/ocr` multipart endpoint.
- Query parameter `languages`, accepting comma or plus separated Tesseract
  language codes, defaulting to `eng`.
- Optional application property `example.ocr.tessdata-path` for local
  traineddata override.
- `SpringBootOcrService` that reads multipart bytes on `Dispatchers.IO`,
  converts them to `ImmutableImage`, builds `OcrOptions`, and calls
  `suspendExtractText`.
- `OcrEngine` bean defaulting to `TesseractOcrEngine`.
- Tests overriding `OcrEngine` with a fake engine.

Decision: adopt. This best matches the issue and the existing Spring Boot image
example while keeping OCR implementation in `images-ocr`.

### Option B — Extend Existing `spring-boot-image-api`

Add `/api/ocr` to `examples/spring-boot-image-api`.

Decision: reject. The existing example is scoped to local storage and
thumbnailing. Mixing OCR into it would hide the `images-ocr` quickstart and make
native setup docs less focused.

### Option C — File Path Endpoint Instead Of Upload

Provide a `path` parameter and let the server read local image files.

Decision: reject for the default example. A multipart endpoint is safer for a
web quickstart and avoids teaching path exposure. File-path OCR can be a local
CLI or advanced workshop topic if needed later.

## API Contract

### `POST /api/ocr`

Request:

- Content type: `multipart/form-data`.
- Part `file`: image bytes.
- Query `languages`: optional string, split on `,` or `+`; defaults to `eng`.

Configuration:

- `example.ocr.tessdata-path`: optional host path passed to
  `OcrOptions.tessdataPath` for local runs.
- The request does not accept a caller-controlled tessdata path.

Validation:

- `file` must not be empty.
- `file.contentType` must be one of `image/jpeg`, `image/png`, `image/webp`,
  or `image/gif`.
- Every parsed language token must be non-blank.

Response:

```json
{
  "text": "recognized text",
  "languages": ["eng"],
  "characterCount": 15
}
```

Error mapping:

- Caller validation failures return HTTP 400 with `{ "error": "bad_request",
  "message": "..." }`.
- `OcrException` failures return HTTP 503 with `{ "error":
  "ocr_unavailable", "message": "..." }` so native Tesseract misconfiguration
  is clearly separated from request validation.

## Architecture

The README architecture diagram must be top-down layered:

1. Client Layer: curl or MockMvc.
2. Spring Web Layer: `OcrApiController`.
3. Application Layer: `SpringBootOcrService`.
4. OCR Library Layer: `ImmutableImage` and `suspendExtractText`.
5. Native Runtime Layer: Tess4J and host Tesseract traineddata.

The diagram must show source-derived relationships and avoid implying that the
example implements a new OCR engine.

## Test Strategy

- Use `@SpringBootTest` and `@AutoConfigureMockMvc`, matching
  `examples/spring-boot-image-api`.
- Generate an in-memory PNG or JPEG fixture in the test.
- Override `OcrEngine` with a fake bean that records the requested
  `OcrOptions` and returns deterministic `OcrResult`.
- Verify:
  - successful multipart request returns recognized text, parsed languages, and
    character count;
  - unsupported content type returns 400;
  - fake `OcrException` returns 503.
- Do not require `tesseract` or traineddata for the default test task.

## Documentation And Registration

- Add `README.md` and `README.ko.md` for the new example.
- Embed PNG diagrams only; keep matching SVG, Graphviz `.dot`, `.plain`,
  `-graphviz.svg`, and `-graphviz.png` evidence.
- Update root `README.md` and `README.ko.md` examples list.
- Update repo-local `AGENTS.md` examples table.
- Update `settings.gradle.kts` with the new module.
- Update `.github/workflows/Examples.yml` matrix and paths so
  `:spring-boot-ocr-api:test` runs with the other examples.

## Acceptance Criteria

- `./gradlew projects` lists `:spring-boot-ocr-api`.
- `./gradlew :spring-boot-ocr-api:test` passes without host-native OCR setup.
- `.github/workflows/Examples.yml` passes `actionlint`.
- README diagram generator renders the new assets and prints deterministic gate
  evidence.
- README links resolve to PNG assets with matching SVG sources.
- `git diff --check` passes.
- Step 6-R 7-tier review has `P0 = 0` and `P1 = 0`.
- PR body records local validation, review evidence, issue #172, milestone
  `0.3.0`, and Step DoD status.

## Risks And Mitigations

- Native Tesseract is unavailable on CI: tests inject fake `OcrEngine`; README
  explains real runtime installation.
- Example becomes production-shaped: keep auth, persistence, queues, and rate
  limits out of scope; file follow-up issues if production concerns are needed.
- OCR failure semantics are unclear: map request validation to 400 and OCR
  runtime/configuration failures to 503.
- README diagrams regress visually: extend the existing generator and inspect
  rendered PNGs individually before PR.
